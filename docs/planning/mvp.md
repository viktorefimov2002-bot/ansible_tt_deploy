# План реализации MVP

План опирается на [спецификацию v0.1](../architecture/product-architecture-spec-v0.1.md), разделы 32–33, и [product baseline](../product/product-spec-v0.1.md). Это дорожная карта, а не набор детальных критериев приёмки будущих TTCP-задач. Конкретный объём и зависимости уточняются в соответствующей задаче.

## Исходное состояние и TTCP-001

Текущая реализация — Ansible/CLI. `AGENTS.md`, навыки и основная спецификация уже существуют; TTCP-001 дополняет их продуктовой основой, индексом архитектуры и правилами/шаблоном ADR. Backend, PostgreSQL, Redis, worker, frontend и Compose остаются целевыми компонентами, а не результатом этой задачи.

Для дорожной карты используется `docs/planning/mvp.md` по текущему заданию вместо `docs/exec-plans/mvp.md`, указанного в спецификации. Индекс архитектуры ссылается на каноническую спецификацию вместо создания её копии в `system-architecture-v0.1.md`. Нумерованные ADR и эксплуатационные runbooks в эту задачу не входят. Поэтому выполнение TTCP-001 в данном объёме не означает выполнения всего Definition of Done архитектурной фазы из раздела 34.

## Основные этапы

| Этап | Направление работ | Связь с roadmap спецификации |
| --- | --- | --- |
| Основа проекта | Продуктовая документация, навигация архитектуры, правила ADR и план MVP. | TTCP-001, текущая задача |
| Реорганизация Ansible | Перенос существующей автоматизации в monorepo layout без функциональных изменений и переписывания ролей. | TTCP-002 |
| Платформа разработки | Подготовка Compose-окружения Control Plane в отдельной задаче. | TTCP-003 |
| Каркас Control Plane | FastAPI и каркас worker с разделением API, бизнес-логики и инфраструктурных адаптеров. | TTCP-004 |
| PostgreSQL | Долговременная модель данных и Alembic migrations; PostgreSQL — source of truth. | TTCP-005 |
| Административная безопасность | Аутентификация, TOTP, сессии, RBAC admin/viewer, аудит и защита секретов. | TTCP-006; требования безопасности действуют и на остальных этапах |
| Redis и worker | Durable jobs в PostgreSQL; очередь, события и координация через абстракции; исполнение worker и live logs. | TTCP-007 |
| Execution adapter | Подключение текущего Ansible через ExecutionPort для операций жизненного цикла. | TTCP-008 |
| Управление серверами | Server CRUD, pre-flight, статусы и затем подготовка managed nodes отдельным bootstrap-node workflow. | TTCP-009–010 |
| Наблюдаемость | node_exporter, VictoriaMetrics, Grafana, агрегация состояния; уведомления в UI по мере готовности интерфейса. | TTCP-011; фаза 7 и последующий notification UX |
| VPN-пользователи и устройства | Доступ к серверам, device_limit, Device × Server credentials, отзыв и expiration. | TTCP-012 |
| Frontend | Client Portal с приглашениями и самообслуживанием; Admin Web для управления, jobs, аудита и уведомлений. | Фазы 9–10 |
| Эксплуатация и проверка готовности | Remote backups, restore/upgrade/runbooks, CI, интеграционные и E2E-проверки, проверка безопасности и отказов. | Фаза 11 |

Тестирование и безопасность сопровождают каждый этап, а не откладываются до завершения UI. Проверки выбираются по изменяемому поведению: права и владение объектами, квоты устройств, секреты, повторные операции и частичные сбои. Для переноса Ansible важно сохранить действующий workflow; для новых компонентов — проверять их реальные контракты и интеграции.

## Границы и зависимые решения

В TTCP-001 не создаются runtime-зависимости, deployment manifests, приложения и `bootstrap-node.sh`. Существующий `bootstrap.sh` сохраняет назначение CLI/Ansible helper. Автоматический rollback Data Plane остаётся будущей функциональностью из спецификации, а не текущей гарантией.

Вопросы SSH trust/ротации ключей, worker library, хранения background jobs и детального восстановления jobs остаются открытыми согласно [правилам ADR](../adr/README.md). Возвращаться к ним следует только при прямой зависимости реализации конкретной задачи; план не выбирает решения заранее.

Рабочие правила и порядок использования источников: [AGENTS.md](../../AGENTS.md). Навигация по компонентам: [индекс архитектуры](../architecture/README.md).
